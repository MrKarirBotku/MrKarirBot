# Audit Produksi MrKarir AI — 1 Agustus 2026

## Ringkasan

Repository sudah memiliki MVP FastAPI, pencarian lowongan, worker sinkronisasi, Telegram bot,
integrasi OpenAI, Docker, Railway, Supabase, dan frontend statis. Proyek belum memenuhi definisi
"enterprise production-ready" karena source database tidak reproducible, frontend belum Next.js,
sebagian besar domain masih berupa fondasi kosong, dan deployment masih bergantung konfigurasi
manual di dashboard provider.

Audit ini tidak mengubah database atau deployment production.

## Kondisi Terverifikasi

- Repository: `MrKarirBotku/MrKarirBot`, default branch `main`.
- Supabase production: aktif dan sehat, PostgreSQL 17.
- Seluruh tabel di schema `public` yang terdeteksi sudah mengaktifkan RLS.
- Supabase security advisor: tidak menemukan lint keamanan.
- Supabase memiliki 13 migration history, tetapi repository hanya menyimpan migration index
  `20260801000000_safe_job_identity_indexes.sql`.
- Tabel `jobs` berisi data nyata; fitur domain lainnya sebagian besar belum memiliki data.
- Frontend masih HTML/CSS/JavaScript di folder `web`, bukan Next.js/React/TypeScript/Tailwind.
- CI Python tersedia, tetapi sebelumnya belum menguji build container.

## Blocker Produksi

### P0 — Database tidak reproducible

Database kosong tidak dapat dibangun dari repository. Migration yang tersedia mengasumsikan tabel
`public.jobs` sudah ada. Ini memblokir onboarding developer, disaster recovery, test migration, dan
deployment lingkungan baru.

Acceptance criteria:

1. Semua object aplikasi, constraint, index, trigger, RLS, policy, function, dan storage policy
   tersedia dalam source control.
2. Baseline berhasil diterapkan ke PostgreSQL/Supabase kosong.
3. Schema hasil baseline dibandingkan dengan production dan tidak memiliki drift yang tidak
   dijelaskan.
4. Security dan performance advisor dijalankan setelah migration.
5. Restore drill terdokumentasi dan pernah berhasil.

### P0 — API berbiaya dan webhook

- Endpoint AI sebelumnya publik tanpa autentikasi.
- Responses API sebelumnya memakai penyimpanan default untuk data karier pengguna.
- Webhook Telegram sebelumnya menerima request tanpa secret jika konfigurasi terlupa.
- Pemrosesan Telegram masih memakai task in-process dan belum durable/idempotent.

Tahap hardening pertama sudah mewajibkan autentikasi AI, menonaktifkan penyimpanan respons AI,
mewajibkan webhook secret, membatasi ukuran request, dan memvalidasi `update_id`. Redis queue,
deduplikasi `update_id`, retry, dead-letter queue, dan persistence state masih harus ditambahkan.

## Roadmap Implementasi

### Tahap 1 — Production foundation

- Production config fail-fast.
- AI authentication, privacy, quota, audit usage, dan structured errors.
- Telegram queue/idempotency/persistence.
- Atomic job ingestion dan provenance sumber.
- Baseline migration serta fresh-database integration test.
- CI lint, unit, integration, container build, dependency dan secret scanning.

### Tahap 2 — Frontend dan auth

- Workspace Next.js terpisah dengan design system dan accessibility baseline.
- Public jobs/detail/blog/FAQ/about/contact dengan SSR/ISR dan SEO.
- Supabase email/Google auth, callback, session refresh, dan protected routes.
- OpenAPI-generated client untuk mencegah drift tipe.

### Tahap 3 — Dashboard pengguna

- Profil, bookmark, tracker lamaran, notifikasi, dan pengaturan.
- CV/sertifikat/portofolio pada private Storage dengan MIME/magic-byte/size validation.
- Delete/export/retention controls untuk data pribadi.

### Tahap 4 — AI workflows

- Career assistant dan riwayat AI.
- CV/ATS, cover letter, interview, matching, skill analysis, salary, dan roadmap.
- Async jobs, quota, retries, prompt versioning, structured output, eval, dan cost monitoring.

### Tahap 5 — Admin dan kanal

- RBAC/permissions yang bersumber dari trusted app metadata/database.
- User/jobs/articles/broadcast/logs/monitoring/backup UI dengan audit trail.
- Telegram production hardening.
- WhatsApp setelah provider, consent, template approval, opt-out, dan retention disepakati.

### Tahap 6 — Staged production release

- Staging lengkap dan E2E/security/performance test.
- Cloudflare DNS/SSL/WAF/origin rules.
- Railway deployment promotion dan rollback runbook.
- Supabase backup/restore drill.
- Canary/cutover domain dan post-deploy verification.

## Keputusan Teknis

- Jangan melakukan migrasi big-bang frontend; jalankan Next.js berdampingan lalu cutover.
- Jangan memasukkan Supabase secret/service-role key ke browser.
- Jangan menyimpan CV atau dokumen pribadi dalam bucket publik.
- Jangan menjalankan migration production dari Alembic dan Supabase secara bersamaan; tetapkan satu
  sumber kebenaran migration sebelum perubahan schema berikutnya.
- Jangan mengaktifkan WhatsApp sebelum core web, auth, database, dan audit stabil.
